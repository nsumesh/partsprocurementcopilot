# Backend — Workers

## backend/app/workers/job_processor.py

**What it does:** Background async coroutine started at FastAPI lifespan. Polls every 30 seconds. In each cycle: (1) fetches jobs in `outreach_sent` or `follow_up_sent` whose `respond_at <= now()` and claims each via a compare-and-set flip to `response_received` *before* any LLM work — concurrent workers or a racing user action simply skip already-claimed jobs — then simulates the vendor response via `response_simulator`, parses it via `email_parser`, and either generates a follow-up email (→ `follow_up_required`) or marks the job `parsed` if all fields are present, writing a `procurement_events` row per transition. (2) Fetches `confirmed` jobs with null `ranking_score`: jobs missing `parsed_unit_price` transition to terminal `failed` instead of looping forever; otherwise the composite score comes from `ranker` and the transition to `ranked` is CAS-guarded on `confirmed` so a user accept/reject racing the cycle is never clobbered. When `urgency_deadline` is set, the `ranked` event metadata includes `meets_deadline` (projected delivery vs deadline). Simulation failures go through `_record_failure`: the claim is released back to the previous status for retry, `attempt_count` increments, the failure event carries the real error text, and after 3 attempts (`_MAX_ATTEMPTS`) the job lands in terminal `failed` instead of burning LLM calls every cycle. Creates its own `AsyncAnthropic` client from settings — initialised inside the loop so a transient failure degrades to a logged retry instead of silently killing the task. Per-job `try/except` keeps one failed job from blocking the rest.

**External services:** Supabase (`procurement_jobs`, `procurement_events`), Anthropic API (via agent modules).

**What calls it:** `app/main.py` lifespan — started as `asyncio.create_task(job_processor_loop(app.state))` and cancelled on shutdown.
